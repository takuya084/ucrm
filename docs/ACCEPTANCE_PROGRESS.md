# リリース前検証の進捗

## 第1弾：事業所境界と無効職員

本番・Macの既存DB/MCP/Runnerには触れず、GitHub CIの専用SQLiteメモリDBだけで検証する。
実Stripe、メール、AI、p-yoyaku APIは呼び出さない。

修正前の回帰テストで、児童登録・更新に他事業所の学校IDを指定すると保存処理が受理され、
無効な職員が無料事業所の児童一覧を閲覧できる状態を確認した。

- 学校の存在検査をログイン職員の事業所で絞る。正規の学校指定と未設定への変更は維持する。
- 業務画面へ進む前に現在の職員所属と有効性を照合する。無料プランでも職員の無効化は尊重する。
- パスワード再設定・本人プロフィール・2FA等の本人用セキュリティ経路は遮断しない。
- 既存の職員ロール（admin/leader/staff）や、機能ごとの許可範囲は変更しない。
- 既に誤った学校を紐付けたデータの自動修復や削除はしない。既存データの確認は別工程。

## 第1弾のテスト実行条件

Laravel起動前に開発用.envを避け、設定読込後・DBアクセス前にSQLite :memory:を検査する。
別接続・Redisを外し、メール・通知・キューはfake、Laravel HTTPの想定外通信とStripe SDKの
通信は拒否する。CIではインターネットもホストのloopbackもないnetwork namespaceで実行する。
依存導入後のpackage:discoverもそのnamespace内で行う。実キーは使用しない。

既存テストのassertionやskipは変更しない。Viteの出力はHTTPテストでのみ代替しているため、
Vue画面の操作や表示・JavaScriptの動作を検証したものではない。

## 第2弾：実ブラウザでの日常操作

修正前の実ブラウザ検証で、児童の編集画面の生年月日が空欄になり、SQLiteでは職員一覧が500になることを確認した。
児童の生年月日・契約開始日・終了日はJSONで年月日のまま返し、UTC変換による前日表示とdate入力の空欄化を防ぐ。
職員のロール順はMySQL専用FIELD()からCASEへ変更し、管理者→児発管→職員、同ロールは氏名順を維持する。
DBスキーマや保存済み日付、権限の許可範囲は変更しない。

`Browser acceptance` CIは本物のVue/ViteビルドをChromiumで開く。
PC幅1280pxとスマートフォン幅390pxで各18シナリオ、合計36ケースを実行する。
モバイル幅のChromiumであり、実機Safariを検証したことにはならない。

- 正誤パスワード、ログイン、メニューからのログアウト。
- 児童登録、学校・利用曜日の保存、検索、契約状態の絞込み。
- 既存日付の編集欄表示、更新後の再読込、学校指定解除、入力エラー。
- 学校登録、職員追加、admin/leader/staffの許可と拒否。
- 他事業所の児童・学校の直接指定拒否、無効職員、ログイン中の職員の無効化。
- 固定スケジュールからの出席保存、支援記録作成、再読込後の紐付け。
- CSV全件中止、児童削除のキャンセルとソフトデリート、CSRF拒否。
- 主要画面の描画と未処理JavaScript例外・HTTP 500の検出。

PHPのfixture CLIが架空の2事業所・8職員・4児童を各ケース前に作り直す。
DBの内容も照合し、画面の成功表示だけで判定しない。通常の認証・権限・CSRFを通す。
fixture用ルートやログイン省略機能を本体へ追加しない。

### ブラウザ検証の隔離

GitHub runnerの専用0700一時ディレクトリ内のSQLiteファイルだけを許可し、
既存の開発.envと設定キャッシュを避ける。fixture CLIはCIフラグ・パス・所有者を確認してからDBを開く。
ネットワークnamespaceには専用loopbackだけがあり、外部サービスやホストのDBへ接続できない。
メール・通知・キューはfake、HTTP/Stripe通信は拒否する。外部フォントとStripe.jsは読み込まない。
課金・メール配信・AI・p-yoyaku実連携の成功を検証するものではない。

Playwrightは自動再試行なし。既存サーバーの再利用なし。保存artifactは件数・成否だけで、
DB・cookie・トークン・trace・動画・スクリーンショット・アプリログは保存しない。
Macでの手動実行は対象外で、PRのCIから実行する。

## 残る工程

- 全画面・全入力境界・アクセシビリティと実機ブラウザの追加検証。
- 他の関連ID、CSV、帳票・請求、連絡帳・同時編集等の検査。請求の制度上の正確性は別確認。
- 職員権限の変更、最後の管理者の保護、事業所停止時の無料/有料の仕様と並行処理。
- ucrm単体の購入導線・メール・Stripeの検証。
- p-yoyakuとの紐付け、予約の同期・変更・取消、再送・順序逆転・切断と復帰、事業所分離。
- 実運用DBのエンジン/バージョン、実メール・実Webhook・実機ブラウザの確認。

第1弾の合格だけで販売リリース可とはしない。
