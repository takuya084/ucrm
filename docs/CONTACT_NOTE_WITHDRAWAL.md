# 連絡帳の公開取り下げ

連絡帳一覧の「公開を取り下げる」で、自施設の連絡帳を下書きへ戻す。確認画面に本文と家庭返信を保持することを表示する。本文・既読・家庭側記入は履歴として残し、物理削除しない。再公開は既存の「公開する」から明示的に行う。支援記録を通常保存するだけでは再公開しない。

ucrmは行ロック内でwithdrawn_atを記録し公開日時を消し、コミット後に既存のPushContactNoteジョブを投入する。ジョブは最新状態を読み直し、公開配信と共通のdelivery_revisionを採番する。取り下げの本文はexternal_ref/user_id/date/revision/withdrawn:true/published_at:nullだけで、施設本文・内部記録・家庭記入は送らない。公開待ちジョブも実行時に取り下げ済みなら取り下げを送る。逆に再公開済みなら最新の公開内容を送る。

p-yoyakuは取り下げ通知を世代チェック後に受信し、published_atだけをnullにして履歴とsource_revisionを保持する。未受信の連絡帳でも非表示の記録を作り、遅れて到着する古い公開や同じ世代の通知で復活させない。再公開後に古い取り下げが到着しても無視する。取り下げに世代番号は必須。事業所・児童・日付・external_refの検証も維持する。

保護者の一覧・閲覧・返信は通常の公開条件から外れるため、取り下げ反映後は404となる。待機中の家庭通知も送信時の公開状態を再確認する。ucrmが非公開中に受信した遅延家庭通知は200/ignoredで更新しない。過去に表示した画面や保存したコピーを回収する仕組みではない。

## 反映待ちと再送

画面は受付と完了を区別する。配信待ち・通信失敗中は「取り下げを連携中」と表示し、保護者側に表示が残る可能性を伝える。連絡帳一覧から「取り下げを再送」で再投入できる。公開を取り下げてから相手の受信が完了するまでは、即時に非表示になる保証はない。実運用には非同期キューワーカーが必要。

## 導入

ucrmの追加migration `2026_10_30_000002_add_contact_note_withdrawn_at.php` が必要。p-yoyakuには今回の追加migrationはないが、直前の世代番号migrationを含めて両アプリを更新する。連携書込みとワーカーを停止し、実行中処理の完了確認・バックアップ・コード/DB更新後、新ワーカーを再起動する。既存の世代や履歴をリセットしない。Mac・実DB・本番への反映は今回行わない。

## 検証と残る範囲

PHPは取り下げ・再公開・他施設拒否・監査・履歴保持・通信失敗時の未完了・古い待機ジョブ・非公開中の家庭通知を検証する。ブラウザは一覧の確認取消/受付/再読込/再公開/他施設拒否をデスクトップとモバイルで確認する。MySQLは旧公開と新取り下げを別プロセスで同時に受信しても非公開が残ることを確認する。実HTTPは実ジョブで取り下げ/再公開し、保護者の通常ログイン・一覧・閲覧・返信と、遅延公開/遅延取り下げ/初回配信前の非表示記録を確認する。

支援記録や連絡帳自体のSoftDeleteに伴う取り下げの自動連携、両アプリMySQL同時稼働、常駐ワーカーの更新/再起動・失敗ジョブ運用の実機確認は別工程。削除操作に今回の非公開化が自動適用されるとは扱わない。
