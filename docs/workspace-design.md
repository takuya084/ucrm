# 業務画面の共通デザイン

参考: p-yoyaku の yoyaku/list・yoyaku/status。UCRM の青いテーマカラーと既存の権限を維持する。

- 見出しは24〜26px、本文は14〜16px、補足・状態は12〜13px。本文全体を小さくしない。
- 背景は薄いグレー、内容は白いカード。カードの見出しと本文を余白・淡い背景で区切る。
- 主操作は既存の青、補助操作は白地。警告・エラーの既存の色分けは残す。
- 一覧の名前・時刻を強調し、補足は小さくする。色だけに意味を持たせない。
- 共通メニュー・入力欄・表・カードは Authenticated レイアウト内で統一する。帳票・印刷用の画面は別扱いとする。
- 今日の業務は「利用児童 → スタッフ全員の送迎 → 療育準備」。各カードから該当位置へ移動できる。
- 請求管理は「実績を確認 → 請求を計算 → 詳細から出力へ」。計算時の再計算警告・確認は変更しない。
- スマートフォンでは案内カードを縦積み、表は内部で横スクロールする。

## 共通送迎入力

p-yoyaku/UCRM は同じ grid.js / grid.css を使う。

- ▼は常に全候補を表示し、現在の入力値を変更しない。
- 文字を入力すると候補を絞る。上下キー・Enterで選択、Escapeで閉じる。
- 5分刻み・登録済みの場所・同事業所の職員という保存制約、複数セルのコピペは維持する。
- 候補を開いただけでは未保存にしない。候補の表示を終了したら追加したDOM・イベントを破棄する。
- XSRF cookie がある場合は現在の値を保存リクエストに使う。419でも保存を自動再試行しない。

## 確認

- ビルド、Node のコピペ・認証ヘッダの回帰テスト。
- Chromium PC/スマートフォン: 入力済みの担当から2候補を表示、選び直し、検索、キーボード、保存、候補の画面内表示、破棄時のクリーンアップ。
- 既存ブラウザ回帰: ログイン、メニュー、児童・記録・請求導線と権限。日別カードの表示と画面横はみ出し。
- データベース・API契約・本番の権限は変更しない。
