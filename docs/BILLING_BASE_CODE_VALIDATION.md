# 基本報酬の一意性・完全性ゲート

## 変更と保存境界

- 請求対象の出席は、利用日に有効な計画の支援時間、サービス種別、対象月、学校日、定員、時間条件で基本コードを照合する。全条件で絞り込んだ候補が **ちょうど1件** の場合のみ算定する。
- 計画時間なし、対象月不一致、コード未登録、条件不一致、複数候補は停止する。先頭候補や実際の滞在時間による代用、固定金額補正はしない。
- Webでは対象日・児童ID・理由コードを `errors.billing` として返す。認証済み共通レイアウトに消えない警告として表示する。最初の問題で停止するため、修正後に別の問題が判明する場合がある。
- 新規月の失敗は期間・明細・明細行・日別算定を残さない。既存下書き再計算の失敗は、その月の既存明細・請求書・日別算定への紐付け・監査記録をトランザクションで復元する。途中まで成功した児童もコミットしない。元の出席実績・計画・受給者証は書き換えない。
- 成功した再計算は従来どおり既存下書きを置換する。成功時の既存請求書削除（明細FK cascade）は従来仕様であり、本変更で一括再計算を実行しない。
- 受給者証欠落で請求対象出席が丸ごと脱落した場合も、月末の完全性検査で保存しない。

## 既存データと出力経路

読み取り専用の共通ゲートは現在の条件と保存済み基本日別算定・明細行・合計単位を照合する。マスターだけを後から追加しても、欠けた算定行は補完されないため旧0円明細の出力は解禁しない。

対象経路:
- 月次確定、明細の手動調整保存（更新後の不整合もロールバック）
- 利用者請求書の一括生成、プレビュー、PDF再生成・ダウンロード、領収書
- 国保連請求CSV、実績CSV、ZIP一括、保存済み出力履歴のダウンロード・送信済マーク
- 実績記録票PDF、代理受領通知書PDF（単独・一括）

元明細と利用者請求書の負担額が不一致でも出力を拒否する。無償化など正当な利用者負担0円は、基本報酬が完全なら拒否しない。現在のマスター・計画と一致しなくなった過去の明細も停止する。確定済みは通常再計算せず、既存の過誤・返戻手順で扱う。

既に利用者端末へダウンロードされたファイルは回収できない。外部へ別途コピーした帳票にはこのアプリのゲートは作用しない。マスターの制度上の正しさ、PDFの文字表示、並行更新下の厳密なスナップショット出力までを保証するものではない。

## 隔離検証

`tests/Feature/Billing/PreflightMay2026BillingTest.php` の12ケース:
1. 条件一致（非ゼロ基本報酬）
2. コードなし
3. 計画時間なし（実滞在時間で代用しない）
4. 適用月不一致
5. 時間区分不一致
6. 全条件で絞っても複数候補
7. 初期候補複数でも条件適用後1件なら成功
8. 後続児童失敗で既存月・請求書・監査記録を完全復元
9. 後続児童失敗で新規月・先行児童も未保存
10. HTTPの対象日・理由付きエラーとリダイレクト
11. 旧不完全明細からの確定・請求書生成・プレビュー・PDF・CSV・ZIP・履歴出力を拒否
12. 正当な利用者負担0円の確定・請求書生成を許可

既存請求計算/CSVテストには明示的なダミー計画時間を追加。概算Seederは実行も変更もしていない。

ローカル隔離MCP（GitHub CIとは別）:

- state: `passed`, exitCode: `0`, durationMs: `4867`
- network none / source read-only / SQLite `:memory:` / 固定全テストスイート
- MCPは個別件数・ソースSHAを返さない。12は追加テストの定義数であり、MCPが返した成功件数ではない。
