# 新規登録データのDB暗号化

新しく登録する個人データを暗号化してDBに保存します。既存データの移行・復旧は行わず、空のDBから利用を始める構成です。

## 保存と通常の操作

- 氏名、メール、電話、住所、LINE連絡先、児童・保護者・職員情報、受給者証、支援記録、予約・シフト・請求内容、監査ログ本文、連携・キュー本文などを対象にします。対象列は `config/privacy.php` に定義します。
- Eloquentと `DB::table()` の保存・読み込みの共通処理で暗号化/復号します。画面とAPIは通常の値を表示します。PDOや直接SQLで読み出した保存値は暗号文です。
- Laravelの `APP_KEY` を使用します。追加の鍵ファイルは不要です。DB暗号化と検索用の鍵は用途を分けて派生させます。保存内容はAES-256-GCMで暗号化・認証します。
- ログインと完全一致・重複確認にはHMAC検索列を使用します。氏名の部分一致、日付検索、並べ替え、金額集計は復号値で処理します。検索用列は画面/APIに返しません。
- ID・外部キー・権限・処理状態・技術的な更新時刻などは構造情報として残します。パスワードやAPIトークンの既存の一方向ハッシュは維持します。DBファイル全体の暗号化ではありません。
- 鍵が無い場合、改ざんされた場合、平文を暗号化済みとして読み込もうとした場合は処理を拒否します。

## 初期設定

1. Laravelの通常の環境設定を行い、`APP_KEY` を用意します。既に設定済みなら、その鍵を使用します。
2. 空のDBに `php artisan migrate --force` を実行し、暗号化用の列・検索用の制約を作成します。その後、通常の登録画面やシーダーからデータを入れます。
3. 既存の開発DBを作り直す場合は、対象が開発DBであることを確認して `php artisan migrate:fresh --force` を実行します。このコマンドは指定DBのデータを削除します。暗号化用の初期設定は、既存行があるDBに対して自動で削除・変換をしません。
4. `php artisan privacy:verify` で平文の残存と認証・HMAC整合性を検査できます。件数のみ表示し、個人情報は出力しません。

Mac manual-demoは専用の起動処理を使います。このPRのマージだけでは起動中のデモは更新されません。新コードを適用し、デモDBを作り直した後にデータを再登録します。

`APP_KEY` はDBへ格納せず、非公開の環境設定で管理してください。データ登録後に変更・紛失すると読めなくなるため、鍵を保管してください。各アプリには別の鍵を設定します。

今回の対象はDBの保存内容です。添付ファイル、ファイルキャッシュ/セッション、アプリログ、バックアップを暗号化するための追加機能・移行コマンドは含めません。認証・事業所ごとの権限確認は従来の仕組みを維持します。
