# 管理者業務マニュアル

放課後等デイサービス uCRM — 管理者（admin / leader）向け運用手順書

このマニュアルは、本アプリで管理者が行う業務を **日次 → 月次 → 年次** の時系列で整理したものです。各項目の末尾に対応する画面名とルート名を記載しています。

## 1. 事前準備（初回セットアップ）

導入直後、または管理者引き継ぎ時に一度だけ行う作業です。

| # | 作業 | 画面 | ルート名 |
|---|------|------|---------|
| 1-1 | 事業所情報（事業所名・事業所番号・住所・法人情報）を登録 | 事業所設定 | `facility.edit` |
| 1-2 | サービスコード単価マスタを取り込み（国保連公開のCSV等） | 請求 > 設定 > サービスコード | `billing.settings.service-codes.import` |
| 1-3 | 自事業所で使うサービスコードの有効化・単価確認 | 同上 | `billing.settings.service-codes` |
| 1-4 | スタッフ登録と権限（admin / leader / staff）設定 | スタッフ管理 | `staff.*` |
| 1-5 | スタッフごとの勤務パターン登録 | スタッフ > 勤務パターン | `staff.work-patterns.edit` |
| 1-6 | シフトラベル（早番・遅番等）の登録 | シフトラベル | `shift-labels.index` |
| 1-7 | 学校マスタの登録 | 学校 | `schools.*` |
| 1-8 | 外部事業所（上限管理・多機関併用用）の登録 | 外部事業所 | `external-facilities.*` |
| 1-9 | 児童の基本情報・受給者証を登録 | 児童 > 登録 | `children.create` |

> **ポイント：** 受給者証の「支給量（月）」「上限月額」「有効期間」は請求・上限管理に直結するため、必ず原本と照合して入力してください。

## 2. 日次業務

毎日の定常業務です。朝礼前・夕方締め時に実施することを推奨します。

### 2-1. 朝（開所前）

1. **ダッシュボード確認** (`dashboard`)
   - 当日予定の児童数、スタッフ出勤状況、未対応タスクの有無を把握
2. **当日シフト確認** (`shifts.index`)
   - 出勤予定のスタッフ・役割に漏れがないか
3. **利用予定の確認** (`usage-records.index`)
   - 当日の登所予定児童、送迎要否、欠席連絡の反映

### 2-2. 日中

4. **欠席連絡が入ったら即時反映**
   - 利用記録画面で該当児童の当日行を「欠席（連絡あり／なし）」に変更
   - 「欠席時対応加算」の算定要件を満たす場合はステータスを `absent_notice` に
   - 画面：利用記録一覧 → 当日該当児童の行 → `usage-records.bulk-store`
5. **問い合わせ対応** (`inquiries.*`)
   - 新規問い合わせを登録 → 担当者アサイン → ステータス更新

### 2-3. 夕方（閉所前〜閉所後）

6. **支援記録（連絡帳）の入力** (`support-records.create`)
   - その日の様子・プログラム実施内容・特記事項を児童ごとに入力
   - 保護者に見せる内容のため、敬体で記載
7. **プログラム進捗の記録** (`program-progress.index`)
   - 個別支援計画に紐づくプログラムの進捗を更新
8. **送迎実績・延長の確定**
   - 利用記録の `is_pickup` / `is_dropoff` / `is_extension` を確定

### 2-4. 日次チェックリスト

- [ ] 当日の全児童の利用記録が登所・退所時刻まで埋まっているか
- [ ] 欠席児童の理由区分が正しく入っているか
- [ ] 支援記録が全員分入力されているか
- [ ] シフトの実績が予定と乖離していないか

## 3. 週次業務

### 3-1. 翌週シフト作成（毎週木〜金を目安に）

1. シフト一覧 (`shifts.index`) で翌週を表示
2. 新規シフト枠を作成 (`shifts.create`)
3. スタッフ割当を一括保存 (`shifts.bulk-save`)
4. 確定したらステータスを「確定」へ (`shifts.update-status`)

### 3-2. 空き枠調整

- **空き調整画面** (`vacancy-adjustment.index`) で、定員に対する予約状況を確認
- 空きがある日は新規問い合わせ対応や体験受入の検討材料に

### 3-3. 問い合わせ棚卸し

- 未対応・保留の問い合わせを一覧で確認し、放置がないかチェック (`inquiries.index`)

## 4. 月次業務（当月中）

### 4-1. 月初：個別支援計画・モニタリングの期限チェック

1. **期限切れ・期限間近の個別支援計画を確認**
   - 各児童の詳細画面 (`children.show`) または児童一覧から
   - 有効期限 90 日以内の計画は更新準備、期限切れは算定不可リスクのため最優先
2. **モニタリング実施予定の確認**
   - `next_review_date` が近い児童を洗い出し、面談日程を調整
3. **AIドラフト活用**
   - 個別支援計画 / モニタリングは `ai-draft.support-plan` / `ai-draft.monitoring` でドラフト生成可能
   - 生成結果を必ず人が確認・修正してから保存

### 4-2. 個別支援計画の更新フロー

| 手順 | 操作 |
|------|------|
| ① | 児童詳細 → 「個別支援計画を作成」 (`children.support-plans.create`) |
| ② | 前回計画をコピー元として読み込み、目標・方針・プログラムを更新 |
| ③ | 保存 (`children.support-plans.store`) |
| ④ | **PDF出力**ボタンから個別支援計画書を印刷 (`children.support-plans.pdf`) |
| ⑤ | 保護者面談で説明 → 同意印をもらう |
| ⑥ | 同意後、計画画面で `guardian_agreement = true`・`guardian_agreement_date` を入力 (`children.support-plans.update`) |

### 4-3. モニタリングの実施フロー

| 手順 | 操作 |
|------|------|
| ① | 児童詳細 → 「モニタリング記録を作成」 (`children.monitoring.create`) |
| ② | 対象期間・経過まとめ・強み／課題・保護者ニーズ等を入力 |
| ③ | 次回予定日 `next_review_date` を必ず設定 |
| ④ | **PDF出力**ボタンから配布 (`children.monitoring.pdf`) |
| ⑤ | 保護者確認・署名 |

### 4-4. 月中の受給者証チェック

- 月途中で有効期限切れとなる受給者証がないか児童一覧で確認
- 更新があれば新しい受給者証情報（期間・支給量・上限月額）を登録

## 5. 月次業務（翌月1日〜10日：国保連請求）

**国保連への請求提出期限は原則毎月10日**。以下のフローで進めます。

### 5-1. 前月利用実績の確定（翌月1日〜3日）

1. **利用記録の抜け漏れ最終チェック** (`usage-records.index`)
   - 欠席連絡区分、送迎、延長の入力漏れを確認
2. **日々の算定明細の確認** (`billing.daily-records.index`)
   - 個別支援計画未策定減算、欠席時対応加算などが正しく付与されているか
   - 修正が必要なら一括更新 (`billing.daily-records.bulk-update`)

### 5-2. 月次請求の計算（翌月3日〜5日）

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 請求一覧から対象月の請求期間を作成・計算 | `billing.calculate` |
| ② | 計算結果（事業所合計・児童別明細）を確認 | `billing.show` |
| ③ | 明細に異常値がある児童は個別編集 | `billing.details.edit` / `billing.details.update` |
| ④ | 事前検証（CSV整形チェック） | `billing.validate-export` |

### 5-3. 上限管理（多機関併用児童）

多機関併用児童がいる場合、管理事業所として実施：

1. 上限管理画面を開く (`billing.cap-management.index`)
2. 対象月で計算 (`billing.cap-management.calculate`)
3. 他事業所からの金額情報を明細に入力 (`billing.cap-management.details.update`)
4. ステータス遷移（入力中 → 確定 → 送付済） (`billing.cap-management.transition`)
5. 上限管理票CSVを出力 (`billing.cap-management.export`)

### 5-4. 確定と国保連CSV出力（翌月5日〜10日）

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 請求期間を確定（以降編集不可） | `billing.confirm` |
| ② | 国保連提出CSVを出力 | `billing.export` |
| ③ | 実績記録票CSVを出力 | `billing.export-performance` |
| ④ | CSV＋関連ファイル一括ZIP | `billing.export-bundle` |
| ⑤ | 国保連電送ソフトへ取込・送信 | （外部） |
| ⑥ | 送信完了後、エクスポート履歴を「送信済」に | `billing.exports.mark-submitted` |

### 5-5. 実績記録票PDF（保護者確認印用）

- 全児童一括ZIP：請求期間画面の「実績記録票PDF一括」(`billing.performance-pdf-bundle`)
- 個別：請求明細画面の「実績記録票PDF」(`billing.details.performance-pdf`)
- 印刷 → 保護者確認印をもらい保管

## 6. 月次業務（翌月中旬〜月末：利用者請求・入金管理）

### 6-1. 利用者請求書の発行（翌月10日〜15日）

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 利用者請求書一覧 | `billing.invoices.index` |
| ② | 対象月で一括生成 | `billing.invoices.generate` |
| ③ | 内容確認（利用者負担・おやつ代等実費） | `billing.invoices.show` |
| ④ | PDFダウンロード → 保護者配布 | `billing.invoices.pdf` |

### 6-2. 入金消込

- 保護者からの入金を確認したら、請求書ごとに入金ステータスを更新 (`billing.invoices.update-payment`)
- 月末時点で未入金の請求書を棚卸し、督促対応

## 7. 返戻・過誤対応（随時）

国保連から返戻・増減単位通知が届いた際の対応です。

### 7-1. 返戻対応

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 返戻一覧を開く | `billing.returns.index` |
| ② | 返戻CSVを一括インポート（または手動登録 `billing.returns.store`） | `billing.returns.import` |
| ③ | 返戻理由を確認し、原因データ（利用記録・明細）を修正 | — |
| ④ | 再請求処理 | `billing.returns.resubmit` |
| ⑤ | ステータス遷移（返戻中 → 再請求済 → 解決） | `billing.returns.transition` |

### 7-2. 過誤申立

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 過誤申立一覧 | `billing.error-claims.index` |
| ② | 対象の請求明細から過誤申立を作成 | `billing.error-claims.create` |
| ③ | 保存 | `billing.error-claims.store` |
| ④ | 過誤申立書CSV出力 → 国保連提出 | `billing.error-claims.export` |

## 8. 年次業務

### 8-1. 年度末（3月）

- [ ] 全児童の個別支援計画・モニタリング実施状況の棚卸し
- [ ] 受給者証の更新（4月からの新年度分）登録準備
- [ ] スタッフ配置体制の見直し（新年度のシフト・勤務パターン）
- [ ] **分析画面** (`analysis`) で年度指標（延べ利用日数・加算算定率・稼働率）の年間サマリ確認

### 8-2. 年度初め（4月）

- [ ] 新年度の受給者証を全員分反映
- [ ] 進級に伴う学校情報の更新（児童ごとに `children.edit`）
- [ ] サービスコード単価の改定（報酬改定年は必須）→ サービスコードマスタ再インポート
- [ ] 新年度の個別支援計画を順次作成

### 8-3. 年1回の棚卸し

- [ ] 退所児童のアーカイブ、契約終了処理
- [ ] スタッフ退職者の権限無効化
- [ ] 外部事業所マスタの棚卸し（廃止事業所の整理）

## 9. トラブル時の確認フロー

### 9-1. 請求金額が合わない

1. `billing.daily-records.index` で日次算定明細を確認
2. 個別支援計画の有効期間を確認（切れていると減算）
3. 受給者証の支給量・上限月額を確認
4. サービスコード単価マスタが最新か確認

### 9-2. 国保連CSVでエラーが出た

1. `billing.validate-export` で事前検証
2. 事業所番号・受給者証番号の桁数・半角を確認
3. 必要に応じて請求期間の確定を解除して修正（admin権限）

### 9-3. 上限額管理がずれる

1. 上限管理票の管理事業所・関係事業所の設定確認
2. 他事業所からの金額情報が最新か確認
3. `billing.cap-management.attributes` で属性修正
