# 管理者業務マニュアル

放課後等デイサービス uCRM — 管理者（admin / leader）向け運用手順書

このマニュアルは、本アプリで管理者が行う業務を **日次 → 月次 → 年次** の時系列で整理したものです。各項目の末尾に対応する画面名とルート名を記載しています。

> **迷ったら：** ダッシュボードの「前月分の国保連請求」カードと、請求詳細画面のステップガイド（①請求計算→⑥支払突合）に「次にやること」が常に表示されます。基本はその案内に従ってください。

## 1. 事前準備（初回セットアップ）

導入直後、または管理者引き継ぎ時に一度だけ行う作業です。

| # | 作業 | 画面 | ルート名 |
|---|------|------|---------|
| 1-1 | 事業所情報を登録：事業所名・**事業所番号（10桁）**・住所・**地域区分単価**・**地域区分コード（1〜20級地）** | 施設設定 | `facility.edit` |
| 1-2 | サービスコード単価マスタを取り込み（こども家庭庁告示の単位数表に基づくもの） | 請求 > 設定 > サービスコード | `billing.settings.service-codes.import` |
| 1-3 | 自事業所で使うサービスコード（加算）の有効化・単価確認 | 同上 | `billing.settings.service-codes` |
| 1-4 | スタッフ登録と権限（admin / leader / staff）設定 | スタッフ管理 | `staff.*` |
| 1-5 | スタッフごとの勤務パターン登録 | スタッフ > 勤務パターン | `staff.work-patterns.edit` |
| 1-6 | シフトラベル（早番・遅番等）の登録 | シフトラベル | `shift-labels.index` |
| 1-7 | 学校マスタの登録 | 学校 | `schools.*` |
| 1-8 | 外部事業所（上限管理・多機関併用用）の登録。**事業所番号も入力** | 外部事業所 | `external-facilities.*` |
| 1-9 | 児童の基本情報を登録。**氏名カナは必須運用**（国保連CSVのカナ欄に使用） | 児童 > 登録 | `children.create` |
| 1-10 | 保護者情報（**カナ含む**）を登録し、主たる保護者を設定 | 児童詳細 > 保護者 | `children.show` |
| 1-11 | 受給者証を登録：番号・**市区町村コード（6桁）**・支給量・上限月額・有効期間 | 児童詳細 > 受給者証 | `children.show` |
| 1-12 | **契約情報を登録**：契約支給量・契約開始日・事業者記入欄番号（国保連明細書の契約情報レコードに出力） | 児童詳細 | `children.show` |

> **ポイント：** 受給者証の「支給量（月）」「上限月額」「有効期間」「市区町村コード」は請求・上限管理に直結するため、必ず原本と照合して入力してください。地域区分コード・カナ氏名が未入力のままだと、国保連CSV出力前のチェックでエラー／警告になります。

## 2. 日次業務

毎日の定常業務です。朝礼前・夕方締め時に実施することを推奨します。

### 2-1. 朝（開所前）

1. **ダッシュボード確認** (`dashboard`)
   - 当日予定の児童数、受給者証期限・モニタリング期限・計画同意待ちのアラート
   - 月初（1〜10日）は「前月分の国保連請求」カードの状態も確認
2. **当日シフト確認** (`shifts.index`)
3. **利用予定の確認** (`usage-records.index`)
   - 当日の登所予定児童、送迎要否、欠席連絡の反映

### 2-2. 日中

4. **欠席連絡が入ったら即時反映**
   - 出欠管理画面で該当児童の当日行を「欠席（連絡あり／なし）」に変更
   - 「欠席時対応加算」の算定要件を満たす場合はステータスを「欠席（連絡あり）」に。欠席理由・対応内容はメモ欄へ
   - 出欠・送迎チェック・欠席理由・メモは**変更すると自動保存**されます
5. **問い合わせ対応** (`inquiries.*`)

### 2-3. 夕方（閉所前〜閉所後）

6. **支援記録（連絡帳）の入力** (`support-records.create`)
7. **プログラム進捗の記録** (`program-progress.index`)
8. **送迎実績・延長の確定**（出欠管理画面のチェックで自動保存）

### 2-4. 日次チェックリスト

- [ ] 当日の全児童の利用記録が登所・退所時刻まで埋まっているか
- [ ] 欠席児童の理由区分・メモが正しく入っているか
- [ ] 支援記録が全員分入力されているか
- [ ] シフトの実績が予定と乖離していないか

## 3. 週次業務

### 3-1. 翌週シフト作成（毎週木〜金を目安に）

1. シフト一覧 (`shifts.index`) で翌週を表示
2. 新規シフト枠を作成 (`shifts.create`)
3. スタッフ割当を一括保存 (`shifts.bulk-save`)
4. 確定したらステータスを「確定」へ (`shifts.update-status`)

### 3-2. 空き枠調整

- **空き調整画面** (`vacancy-adjustment.index`) で、定員に対する予約状況を確認

### 3-3. 問い合わせ棚卸し

- 未対応・保留の問い合わせを一覧で確認 (`inquiries.index`)

---

## 4. 月次業務（当月中）

### 4-1. 月初：計画・モニタリングの期限チェック

1. **期限切れ・期限間近の個別支援計画を確認**
   - ダッシュボードのアラート、または児童詳細のタブの赤丸表示から
   - 期限切れは未策定減算のリスクがあるため最優先
2. **モニタリング実施予定の確認**（`next_review_date` が近い児童）
3. **AIドラフト活用**
   - 個別支援計画 / モニタリングは AI でドラフト生成可能（`ai-draft.support-plan` / `ai-draft.monitoring`）
   - **保護者のAI利用同意**（児童フォームの同意チェック）がない児童には使用不可
   - 生成結果は必ず人が確認・修正してから保存

### 4-2. 個別支援計画の作成〜交付フロー

計画詳細画面に「原案作成 → 児発管承認 → 同意・交付」の3ステップが表示され、現在の段階が分かります。

| 手順 | 操作 |
|------|------|
| ① | **アセスメントを実施・記録**（心身の状況・生活環境・本人と保護者の意向・5領域別の発達状況） (`children.assessments.create`) |
| ② | 児童詳細 → 「個別支援計画を作成」 (`children.support-plans.create`) |
| ③ | 目標・支援方針に加え、**計画支援時間（開始・終了・支援時間数）を必ず入力**（R6報酬改定により基本報酬の時間区分判定に使用。未入力だと請求計算で時間区分を判定できません）。**5領域との関連**も入力 |
| ④ | 児童発達支援管理責任者が内容を確認し「承認」 (`children.support-plans.approve`) |
| ⑤ | **担当者会議を開催し記録**（開催日・出席者・検討内容） (`children.support-plans.meetings.store`) |
| ⑥ | PDF出力 (`children.support-plans.pdf`) → 保護者面談で説明 |
| ⑦ | **同意・交付を記録**（同意した保護者・同意日・方法［書面/電子］・交付日） (`children.support-plans.consents.store`)。交付日を入れると計画は「交付済」になります |

### 4-3. モニタリングの実施フロー

| 手順 | 操作 |
|------|------|
| ① | 児童詳細 → 「モニタリング記録を作成」 (`children.monitoring.create`) |
| ② | 対象期間・経過まとめ・強み／課題・保護者ニーズ等を入力 |
| ③ | 次回予定日 `next_review_date` を必ず設定 |
| ④ | PDF出力 (`children.monitoring.pdf`) → 保護者確認・署名 |

### 4-4. 月中の受給者証チェック

- 児童一覧 (`children.index`) の「受給者証期限」列で確認（30日以内は黄色、期限切れ・未登録は赤）
- 更新があれば新しい受給者証情報（期間・支給量・上限月額・市区町村コード）を登録

## 5. 月次業務（翌月1日〜10日：国保連請求）

**国保連への請求提出期限は原則毎月10日**。請求詳細画面のステップガイド「①請求計算 → ②内容確認 → ③確定 → ④CSV出力 → ⑤国保連へ伝送 → ⑥支払突合」に沿って進めます。

### 5-1. 前月利用実績の確定（翌月1日〜3日）

1. **利用記録の抜け漏れ最終チェック** (`usage-records.index`)
   - 欠席連絡区分、送迎、延長、登所・退所時刻の入力漏れを確認
2. **実績記録票（日別明細）の確認** (`billing.daily-records.index`)
   - 時刻・授業日/休業日・サービス提供状況は**この画面で直接修正して一括保存**できます（修正後は再計算が必要）
   - 請求確定後はロックされ閲覧のみになります

### 5-2. 月次請求の計算（翌月3日〜5日）

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 請求管理で対象月を選び「計算実行」 | `billing.calculate` |
| ② | 請求詳細で児童別明細を確認。**「✕要修正」「⚠要確認」バッジをゼロにする** | `billing.show` |
| ③ | 明細を手動調整する場合は個別編集。**調整理由の入力が必須**（監査ログに記録） | `billing.details.edit` |
| ④ | 出力前 整合性チェック（別途出力メニュー内） | `billing.validate-export` |

> **注意：** 「計算実行」をやり直すと、手動調整を含む既存明細はすべて削除され作り直されます（実行前に警告が表示されます）。

### 5-3. 上限管理（多機関併用児童）

多機関併用児童がいる場合、管理事業所として実施：

1. 上限管理画面を開く (`billing.cap-management.index`)
2. 対象月で計算 (`billing.cap-management.calculate`)
3. 他事業所からの金額情報を明細に入力 (`billing.cap-management.details.update`)
4. ステータス遷移（入力中 → 確定 → 送付済） (`billing.cap-management.transition`)
5. 上限管理結果票CSV（K41ファイル）を出力 (`billing.cap-management.export`)

### 5-4. 確定と国保連CSV出力（翌月5日〜10日）

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 請求詳細右上の「確定する」（以降、再計算・実績変更不可） | `billing.confirm` |
| ② | 「複式CSV一括出力（ZIP）」でダウンロード | `billing.export-bundle` |
| ③ | ZIP内のCSVを国保連の**電子請求受付システム（取込送信）**でアップロード・送信 | （外部） |
| ④ | 送信完了後、出力履歴の「送信済マーク」を押す → **請求月が自動的に「提出済」になる** | `billing.exports.mark-submitted` |

出力されるCSVは**インタフェース仕様書（令和7年4月版）準拠**の交換情報ファイルです：

| ファイル名 | 内容 |
|---|---|
| `K11xxxx.CSV` | 請求書（K112）＋明細書（K122） |
| `K61xxxx.CSV` | サービス提供実績記録票（K611） |
| `K41xxxx.CSV` | 利用者負担上限額管理結果票（K411。管理事業所のときのみ） |

> **初回提出前に：** 国保連の取込送信システム／簡易入力システムで事前検証を行ってください。形式エラーが出た場合は `docs/nhif-csv-todo.md` を参照。

### 5-5. 実績記録票PDF（保護者確認印用）

- 全児童一括ZIP：請求詳細の「別途出力 > 実績記録票PDF（全員ZIP）」(`billing.performance-pdf-bundle`)
- 個別：児童別明細の「実績票PDF」(`billing.details.performance-pdf`)
- 印刷 → 保護者確認印をもらい保管

## 6. 月次業務（提出後：支払突合・利用者請求・入金管理）

### 6-1. 国保連 支払決定通知との突合

国保連から支払決定通知が届いたら（提出済の月のみ表示されます）：

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 請求詳細の「支払決定通知との突合」カードに通知記載の**支払決定額・支払決定日**を入力 | `billing.payment-decision` |
| ② | 金額が一致 → その月は自動的に「**完了**」になる | — |
| ③ | 差異がある → 差異メモ（原因）の入力が必須。返戻管理・過誤申立で原因に対応 | `billing.returns.index` / `billing.error-claims.index` |

### 6-2. 利用者請求書の発行（翌月10日〜15日）

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 利用者請求一覧（回収サマリ：請求合計・入金済・**未回収**・未入金件数が上部に表示） | `billing.invoices.index` |
| ② | 対象月で一括生成 | `billing.invoices.generate` |
| ③ | 内容確認（利用者負担・おやつ代等実費） | `billing.invoices.show` |
| ④ | 請求書PDFダウンロード → 保護者配布 | `billing.invoices.pdf` |

### 6-3. 入金消込と領収書発行

- 入金を確認したら、一覧の「**入金記録**」ボタンでその場で入金日・方法・金額を記録（全額なら「入金済」、一部なら「一部入金」に自動判定）
- 入金記録済みの請求書は「**領収書**」リンクから領収書PDFを発行（再発行しても領収書番号は同一）(`billing.invoices.receipt-pdf`)
- 月末時点で未入金の請求書を棚卸し、督促対応

### 6-4. 代理受領額通知書の交付

確定済み以降の月では、法定代理受領額の通知書を発行できます：

- 全員一括ZIP：請求詳細の「別途出力 > 代理受領額通知書PDF（全員ZIP）」(`billing.proxy-receipt-bundle`)
- 個別：児童別明細詳細の「代理受領額通知書PDF」(`billing.details.proxy-receipt-pdf`)
- 印刷して保護者に交付

## 7. 返戻・過誤対応（随時）

国保連から返戻・増減単位通知が届いた際の対応です。

### 7-1. 返戻対応

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 返戻一覧を開く | `billing.returns.index` |
| ② | 返戻CSVを一括インポート（または手動登録 `billing.returns.store`） | `billing.returns.import` |
| ③ | 返戻理由を確認し、原因データ（利用記録・明細）を修正 | — |
| ④ | 再請求処理 | `billing.returns.resubmit` |
| ⑤ | ステータス遷移（返戻中 → 再請求済 → 解決） | `billing.returns.transition` |

### 7-2. 過誤申立

| 手順 | 操作 | ルート |
|------|------|--------|
| ① | 過誤申立一覧 | `billing.error-claims.index` |
| ② | 対象の請求明細から過誤申立を作成 | `billing.error-claims.create` |
| ③ | 保存 | `billing.error-claims.store` |
| ④ | 過誤申立書CSV出力 → 国保連提出 | `billing.error-claims.export` |

## 8. 運営記録（委員会・研修・BCP・自己評価）

**運営記録ページ**（メニュー > 運営記録、leader以上）(`operation-records.index`) で、指定基準・減算に関わる運営上の記録を管理します。タブごとに未実施が赤く表示されます。

| タブ | 記録する内容 | 頻度の目安 |
|------|------|------|
| 委員会・研修 | 虐待防止委員会・身体拘束適正化委員会の開催、虐待防止・身体拘束の研修実施（年度内の実施回数が0のカテゴリは赤表示） | 定期的（年度内に必ず実施） |
| 身体拘束記録 | やむを得ず身体拘束を行った際の記録（日時・態様・理由）。**保護者への報告が未了だと赤ボタン表示** → 報告したら「報告済にする」 | 発生の都度 |
| BCP・安全計画 | 業務継続計画（感染症・災害）と安全計画の策定・見直し。**未策定は「減算対象」バッジ**が表示 | 策定後、定期見直し |
| 自己評価公表 | 自己評価・保護者評価の実施と公表記録。**未公表は「減算対象」バッジ** | 年1回以上 |

## 9. 年次業務

### 9-1. 年度末（3月）

- [ ] 全児童の個別支援計画・モニタリング実施状況の棚卸し
- [ ] 受給者証の更新（4月からの新年度分）登録準備
- [ ] スタッフ配置体制の見直し（新年度のシフト・勤務パターン）
- [ ] **自己評価・保護者評価の実施と公表** → 運営記録に記録 (`operation-records.index`)
- [ ] BCP・安全計画の年次見直し
- [ ] 事業所KPI（利用率・キャンセル率・売上推移・損益）を請求詳細画面で年間確認 (`billing.show`。損益はadminのみ表示)

### 9-2. 年度初め（4月）

- [ ] 新年度の受給者証を全員分反映
- [ ] 進級に伴う学校情報の更新（児童ごとに `children.edit`）
- [ ] サービスコード単価の改定（報酬改定年は必須）→ サービスコードマスタ再インポート
- [ ] 地域区分単価・地域区分コードの改定有無を確認（施設設定）
- [ ] 新年度の個別支援計画を順次作成（アセスメント→計画→承認→会議→同意・交付）

### 9-3. 年1回の棚卸し

- [ ] 退所児童のアーカイブ、契約終了処理
- [ ] スタッフ退職者の権限無効化
- [ ] 外部事業所マスタの棚卸し（廃止事業所の整理）

## 10. トラブル時の確認フロー

### 10-1. 請求金額が合わない

1. `billing.daily-records.index` で日次算定明細を確認
2. **個別支援計画の計画支援時間**を確認（未入力・時間区分違いは基本報酬が変わる）
3. 個別支援計画の有効期間を確認（切れていると未策定減算）
4. 受給者証の支給量・上限月額を確認
5. サービスコード単価マスタ・地域区分単価が最新か確認

### 10-2. 国保連CSVでエラーが出た

1. 請求詳細の「出力前 整合性チェック」を実行（事業所番号10桁・市区町村コード6桁・地域区分コード・カナ氏名・支給量超過・受給者証期間を自動チェック）
2. エラー項目を施設設定・児童情報・受給者証で修正し、再出力
3. **確定後の金額修正はできません。** 内容の誤りは過誤申立（提出後）または返戻対応で処理してください
4. 取込送信システム側のエラーコードは `docs/nhif-csv-todo.md` の仕様参照先を確認

### 10-3. 上限額管理がずれる

1. 上限管理票の管理事業所・関係事業所の設定確認
2. 他事業所からの金額情報が最新か確認
3. `billing.cap-management.attributes` で属性修正

### 10-4. 支払決定額が請求額と合わない

1. 請求詳細の突合カードで差異額（超過／不足）を確認
2. 返戻一覧に該当児童がないか確認（返戻分は支払から除かれる）
3. 原因を差異メモに記録（記録しないと保存できません）
4. 返戻→再請求、または過誤申立で対応
