# 日々の連絡帳

1. p-yoyakuの保護者画面で「連絡帳」を開き、利用予約のある日を選び「家庭からの連絡を入力する」。体調・睡眠・服薬・連絡事項を保存する。事業所の公開は不要。
2. ucrmの同日の「連絡帳」で家庭からの連絡を読み、「家庭からの連絡を確認した」を押す。家庭の更新が届くと再確認待ちになる。
3. 利用後、従来の支援記録画面で事業所の様子を記入し、保護者へ公開する。内部の見立てや申し送りは公開しない。
4. 保護者はp-yoyakuで公開内容を読み、「内容を確認して確認印を押す」。単に開いた既読とは区別する。
5. ucrmの一覧・支援記録画面で確認印と日時を確認する。公開内容が変わった場合は新しい確認印が必要。家庭側だけの編集や同じ本文の再送では保護者の確認印は解除しない。

## 更新と連携

p-yoyaku PR #25とucrm PR #13を組み合わせて使用する。各アプリの2026_11_07_000001_add_contact_note_workflow migrationを適用する。既存データは削除・初期化しない。アプリ・ワーカー間の連携書込みを止め、実行中処理が終わった状態で両方のコードとmigrationを揃え、新コードのワーカーを再開する。実環境への反映はこのPRに含まれない。

利用前の連絡には署名付きcontact_note.pre_use_entryと不変UUID・単調な家庭記入世代を使う。公開時は同じ児童・日付の保護者用仮レコードへ施設側の参照を結び付け、家庭の入力を保持する。確認印は署名付きcontact_note.confirmedで、公開内容のSHA-256と日時を送る。本文の内容と公開日時が違う古い確認印は反映しない。既存の既読・家庭返信のイベントも互換性を維持する。

## Mac手動デモ

現在のデモは固定コードをDockerイメージに焼き込んでいる。git pullやresumeだけでは新機能は適用されない。両PRのマージ後、既存のデータvolumeを保持したイメージ更新とmigrationが別工程として必要。prepare/startのやり直し、volumeや.runtimeの削除、migrate:freshは行わない。
