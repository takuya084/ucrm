# 登録・CSV・アカウント作成時の重複予防

## 児童の登録・編集

同じ施設の有効な児童で、同じyoyaku_user_idを二重登録しない。入力検証に加えて施設行をロックしたトランザクション内で保存直前に再確認する。編集では自分自身を除外する。他施設の同じ番号・削除済み児童の番号・複数児童の未設定nullは許可する。エラーでは氏名等も保存しない。施設設定画面でも他施設が使用中のyoyaku_business_idを入力検証で拒否する。

## 紐付けCSV

- child_idと、yoyaku_user_idまたはyoyaku_emailを指定する。名前による自動突合はしない。
- 同じ児童の複数行、同じ予約アカウントの複数行、別の有効な児童が使用中の番号は全件中止する。同じ紐付けの再取り込みは許可する。
- IDとメールを両方指定した場合は一致が必要。不正なIDをメールへ勝手に読み替えない。メールは前後の空白・大文字小文字を正規化する。利用者一覧のID/メール重複や不正応答も拒否する。
- 施設外・削除済みの児童は対象にしない。HTTP前の紐付けを保持し、保存直前に児童・施設設定を読み直す。途中で変更された場合は上書きしない。
- 同じ施設の登録・編集・紐付けCSV・アカウント作成結果の保存は共通の施設行ロックを使う。全行を確認した後に保存し、失敗時はロールバックする。
- 見出しの不足・重複、列数の相違は保存しない。UTF-8 BOMと従来の文字コード変換を維持し、CSVの引用符はfgetcsvで処理する。

基本情報の児童一括登録CSVはyoyaku_user_idを保存しない経路のため対象外。同姓同名を重複児童と推測して統合・削除する処理は追加しない。

## 予約アカウント作成

選択児童IDは施設内・有効・重複なしで検証し、未紐付け児童のみ処理する。外部作成はexternal_refを維持し、施設専用トークンのハッシュをHTTP生成時に照合する。戻りIDと、存在する場合の事業所番号・資格情報の型を検証する。

通信後に施設と児童を再確認してから紐付ける。既存の別児童とIDが衝突する、児童や施設設定が変更された、不正応答の場合は保存せず、その児童を失敗結果にする。失敗行では戻りメール・パスワードを表示しない。ほかの正常行は保存する従来の部分成功方式を維持する。

外部作成とローカル保存は原子的に実行できない。ローカル紐付けを拒否した時点で外部アカウントは作成済みの可能性がある。失敗を「未作成」と断定しない。外部の自動削除・既存紐付けの自動統合は行わず、宛先を確認してから再実行する。

## 導入・範囲

追加migrationなし。既存重複の自動修復はしない。入力検証と対象HTTP経路のトランザクションによる防止であり、DBの一意制約は追加しない。直接SQL・独自スクリプト・モデルの直接保存やrestore、施設設定の別施設間同時変更まで保証しない。連携設定変更は既存手順に従い送信とワーカーを止めて行う。

回帰テストは架空データ・SQLite・HTTP fakeを使用する。MySQLでの実際の並行実行、両アプリ同時起動の実HTTP E2E、Mac・本番への反映は別工程。
