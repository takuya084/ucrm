# 予約・連絡帳の送信先確認

送信ジョブ作成時に、施設ID・児童ID・日付・p-yoyaku事業所番号・利用者番号・施設専用トークンのSHA-256ハッシュを保持する。トークン本体や連絡帳の本文はジョブに保存しない。

実行時に現在の紐付けと一致しなければ例外で停止する。再試行で新しい送信先へ勝手に切り替えない。施設番号の重複、施設内の有効な児童番号の重複も拒否する。他施設の同じ児童番号、削除済み重複児童は正常に区別する。予約の同期番号は、この確認が通った後に採番する。従来の予約取消・復活・冪等性は維持する。

連絡帳では、児童が同じ施設に属することに加え、支援記録の児童・日付、紐付いた出欠の施設・児童・日付、公開者や活動の所属施設を確認する。削除済み支援記録等を別の記録で補完しない。保護者向け項目・活動名・時間だけを送信し、支援の内部メモや活動の詳細メモは送らない。送信中に編集・非公開化・削除された連絡帳は、その新しい内容を送信済みとして記録しない。

HTTPクライアント生成時にも保持済みハッシュと実トークンを比較し、途中で変更された資格情報へ切り替えない。HTTP中はDBロックを保持しない。送信後の同期情報の記録も元の施設・児童・日付に限定する。

## 導入と再送

追加migrationなし。両ジョブを実行するワーカーは停止・実行中処理の終了を確認して更新し、新コードで再起動する。旧形式の待機ジョブには送信先の記録がないため、新コードは送信を拒否する。失敗した旧形式ジョブを単純に再試行しても送れない。対象の施設・児童・日付と内容を確認してから、現在の出欠保存・連絡帳公開操作で新しいジョブを登録する。既存ジョブの送信先を直接書き換えない。

施設番号・児童番号・トークン・日付を変更した後も、古いジョブは拒否する。必要な再送は変更後の宛先を確認して新規登録する。未紐付け・存在しない対象や非公開・削除済み連絡帳は送信しない。

## 範囲と制約

この修正は待機中・再試行時の送信先変更、重複紐付け、関連データの取り違えを防ぐ。全設定更新経路の排他や外部HTTPとDBの原子的な一括処理を保証しない。送信開始後の外部への変更取り消しはできず、設定を一旦変更して元に戻す操作の履歴判定もない。連携設定変更時は送信とワーカーを停止する。通常の本文更新は実行時の最新内容を送る。連絡帳の複数送信の順序保証は別工程。

`tests/Feature/OutboundIntegrationTargetTest.php` に架空データ・HTTP fake・ジョブのシリアライズを使った回帰テストを追加。実HTTP E2E・Mac・本番への反映は未実施。
