# 国保連CSV インタフェース仕様準拠対応（P2-6）

**2026-07-05 実装済み。** `NhifCsvExportService` を公式インタフェース仕様書準拠の出力に全面置換した。
残タスクは本ページ末尾の「提出前に必要な作業」を参照。

## 準拠している公式資料

- 障害者自立支援給付支払等システム インタフェース仕様書（**令和7年4月版**）
  - 共通編: https://www.mhlw.go.jp/content/12200000/001469710.pdf
  - サービス事業所編: https://www.mhlw.go.jp/content/12200000/001469723.pdf
  - 複製を `docs/nhif-spec/` に保存済み
- 参照した箇所
  - 共通編 1.2: ファイル形式（コントロール/データ/エンドレコード、Shift_JIS、CRLF、引用符規則）
  - 共通編 1.4: コード一覧（地域区分01〜20、サービス種類 61=児発/63=放デイ、決定サービスコード）
  - 共通編 1.6: データ種別（＝交換情報識別番号の上3桁）
  - 事業所編 2.1.2: 交換情報識別番号（K112/K122/K411/K611）
  - 事業所編 2.1.3.1〜2.1.3.6: 各レコードレイアウト

## 実装構成

| ファイル | 交換情報 | レコード |
|---|---|---|
| `K11{YYMM}.CSV` | 請求書(K112)+明細書(K122) | 請求書: 基本01(23項目)・明細02(14項目)を市町村ごと / 明細書: 基本01(35)・日数02(12)・明細03(11)・集計04(33)・契約05(11)を児童ごと |
| `K61{YYMM}.CSV` | 実績記録票(K611) | 基本01(172項目)・明細02(113項目)。様式種別: 児発=0301, 放デイ=0501 |
| `K41{YYMM}.CSV` | 上限管理結果票(K411) | 基本01(14項目)・明細02(11項目)。上限管理事業所のときのみ |

- 実装: `app/Services/Billing/Nhif/NhifExchangeFileBuilder.php`（ファイル構造）+ `app/Services/Billing/NhifCsvExportService.php`（レコード生成）
- 保存先: `storage/app/billing_csv/{事業所番号}/`（ファイル名は仕様の「英字始まり8桁以内+.CSV」）
- 処理対象年月＝サービス提供月の翌月を設定
- テスト: `tests/Feature/Billing/NhifCsvExportServiceTest.php`

## 主なデータマッピング（判断を伴った箇所）

- 決定利用者負担額 = `cap_result_amount ?? copayment_cap_applied`
- 明細書 集計04 の「利用者負担額②」= `copayment_amount`（無償化対象は計算時に0になっている）
- 単位数単価 = `facilities.area_unit_price × 1000`（10円→10000）
- 実績記録票の算定時間数 = 個別支援計画の `planned_duration_minutes` を優先、なければ実利用時間（R6改定の時間区分ルール）
- 提供形態 = `is_school_day ? 1(授業終了後) : 2(休業日)`
- 欠席（連絡あり）はサービス提供の状況=8（欠席時対応加算）として明細レコードを出力
- 日数情報02の開始年月日 = 契約開始日（契約未登録時は月初）
- **契約情報05の決定サービスコードは基本決定（611000/631000）固定**
  → 重心・医療的ケア児等の決定区分（632000等）の児童は受給者証を確認して要修正（contracts に決定コード欄を追加するのが本筋）

## 提出前に必要な作業（未完了）

1. **取込送信システム／簡易入力システムでの実機検証**（フォーマットエラーの洗い出し。CI組込みは不可なので提出前運用として実施）
2. 施設設定で **地域区分コード** を設定（明細書必須項目。未設定は事前バリデーションでエラー表示）
3. 児童・保護者の **カナ氏名** 整備（半角カナ変換は実装済み。未登録は警告表示）
4. 上限管理結果票の **修正(2)・取消(3) 再提出**は未対応（現状は常に新規(1)。返戻時は手動対応）
5. サービスコード・単位数マスタはこども家庭庁告示の単位数表からの取込みが前提（捏造禁止・従来どおり）
